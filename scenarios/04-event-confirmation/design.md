# 活动提醒与确认设计

## 定位

优先级 P4。验证明确状态流转和结果持久化。

## 目标流程

Agent 读取一条模拟活动记录，向用户确认参加、取消或改期意愿，调用状态更新工具，向用户播报最终状态。

## 第一版范围

- 数据：活动 ID、时间、地点、当前状态。
- 工具：查询活动、确认、取消、提交改期请求。
- 渠道：Web/RTC 模拟提醒，不接真实外呼。
- 暂不做：真实日历、短信、电话运营商和批量任务调度。

## Quickstart 改动点

- 增加活动 fixture 和状态更新 API。
- 保留业务状态机在服务端，Agent 只通过工具改变状态。
- 写操作必须带活动 ID和请求 ID，支持重复请求检查。

## 失败处理

活动不存在、已取消、改期时间不可用或重复提交时返回明确状态，不让 Agent 自由编造成功。
